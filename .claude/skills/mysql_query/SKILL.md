# Mysql数据库查询技能

## 目的
此技能使AI Agent能够：
- 从 MySQL 数据库中检索权威的、针对患者级别的临床信息
- 查找必须来自记录而非推理或生成的医学事实数据
- 核实患者详情、回顾过往护理情况以及检查检查结果
- 将所有数据库访问、验证和执行逻辑委托给本地 Python 脚本
此技能为只读型，适用于医疗信息检索场景。

## When to Use
- 用户提出的问题需要依据特定的患者记录或历史医疗数据（例如，患者信息、就诊记录、检查结果）。
- 分析用户意图和上下文，提取必要的参数（`medical_record_no`, `crm`, `db_name`），并调用此技能。

## Steps
1. 从当前对话上下文中确定患者的病历号（medical_record_no）和 CRM 数据库名称（crm）
2. 根据用户的具体需求选择合适的表名（db_name）：patient_info、visit_record_list 或 examine_result_list
3. 系统向 MySQL 数据库发出查询请求并检索相关数据
4. 返回格式化的结果，供后续医学判断和决策使用

## 参数说明 (Fields)

### medical_record_no
- 类型: String
- 描述: 当前对话的病人病历号，由上下文获取。

### crm
- 类型: String
- 描述: 使用数据库的名称。
- 默认值: "hn"

### db_name
- 类型: String
- 描述: 需要查询的表名称。请根据以下详细说明选择最合适的表：

  1. **patient_info**
     - **适用场景**:
       - 识别患者身份
       - 核实患者的基本属性
       - 检索人口统计信息或登记信息
     - **典型问题**: "这位患者是谁？", "请核对患者的基本信息"

  2. **visit_record_list**
     - **适用场景**:
       - 查询过往或近期的就诊记录
       - 查询科室、就诊时间或就诊摘要
       - 查询按时间顺序排列的护理信息
       - **查询既往诊断、上次就诊的病名**
     - **典型问题**:
       - "患者近期接受过哪些检查？"
       - "回顾一下患者近期的就诊情况"
       - **"我上次得了什么病？"**
       - **"上次诊断是什么？"**
       - **"我的就诊记录"**

  3. **examine_result_list**
     - **适用场景**:
       - 实验检测或检查结果
       - 对检测结果的检验或分析
       - 对实际临床测量数据的审查
     - **典型问题**: "查看病人的检查结果", "检查结果如何？"

## Examples

### 场景 1：识别患者身份 (patient_info)
- **上下文**: System提示或历史对话中已知 "病历号: 1112233"
- **用户**: "我是谁？"
- **操作**: `medical_record_no="1112233"`, `crm="hn"`, `db_name="patient_info"`
- **预期结果**: 返回患者的基本信息（姓名、年龄、性别等）

### 场景 2：回顾就诊记录 (visit_record_list)
- **上下文**: System提示或用户之前提到 "我是病历号 5556677 的张三"
- **用户**: "我最近是否应该就诊"
- **操作**: `medical_record_no="5556677"`, `crm="hn"`, `db_name="visit_record_list"`
- **预期结果**: 返回患者最近的就诊历史和诊断信息

### 场景 3：查询检查结果 (examine_result_list)
- **上下文**: System提示或对话中已确认病历号为 9988776
- **用户**: "医生，我的检验结果怎么样？"
- **操作**: `medical_record_no="9988776"`, `crm="hn"`, `db_name="examine_result_list"`
- **预期结果**: 返回患者的各项检查检验结果和数据

## Constraints

### 安全和隐私
- 医疗数据隐私：仅返回查询的患者数据，不泄露其他患者信息
- 访问权限：确保查询的医生有权访问该患者的记录
- 数据一致性：只读操作，不进行任何数据修改

### 技术限制
- 缓存策略：数据通常是最新的，但可能存在几秒钟的延迟
- 查询限制：单个查询应聚焦于一个患者和一个表
- 字段可用性：不同患者的数据字段可能不同，某些字段可能为空

### 常见错误处理
- 缺少病历号：不能随意生成或猜测病历号，必须从上下文获取
- 无效的表名：仅支持 patient_info, visit_record_list, examine_result_list 三个表
- 数据不存在：某些患者可能没有特定类型的记录，需要妥善处理

## 错误示例 (反例) - 请避免以下行为

### 反例 1：查询通用医学知识
- **用户**: "高血压一般吃什么药？" 或 "胃炎有哪些症状？"
- **错误操作**: 调用 `mysql_query`。
- **原因**: 这是通用医学知识，不属于特定患者的隐私记录。
- **正确操作**: 应该调用 `milvus_query` (向量数据库) 或使用通用知识回答。

### 反例 2：使用不存在的表名 (幻觉)
- **用户**: "查看我的处方详情"
- **错误操作**: `db_name="prescription_details"`
- **原因**: 数据库中不存在 `prescription_details` 表。
- **正确操作**: 将意图映射到现有的表，例如 `visit_record_list` (就诊记录通常包含处方摘要) 或 `examine_result_list`。如果无法映射，请勿调用。

### 反例 3：缺少病历号
- **用户**: "我以前得过什么病？" (但当前对话上下文中从未提及病历号)
- **错误操作**: 随机生成或猜测一个病历号进行查询。
- **正确操作**: 拒绝调用技能，并向用户询问病历号。
