## 1. 项目定位（一句话）

一个**多租户医疗 AI 智能体 + 技能（Skill）管理可插拔系统**：

- 用 **LangGraph** 编排"数智医生"的多步对话（预处理 → 技能检索 → 大模型回答 → 后处理）；
- 把"医生（Agent）/技能（Skill）"的**加载、启用、隔离**做成一套 FastAPI 后端 + Vue3 Web 界面；
- 技能分为**内置技能**（MySQL 患者档案、Milvus 医学知识、Tavily 网络搜索、YOLO 皮肤病检测）与**用户自定义技能**（按 `user_skills/{user_id}/` 热加载）；
- 当前分支用于**研究 OpenSkills 与 Qwen（通义千问）**的相关改造（见 [README.md](README.md#L6)）。

## 5. 核心机制详解

### 5.1 Agent 与 LangGraph 图

Agent 主类 [digital_smart_doctor_agent.py](agent/digital_smart_doctor_agent.py)：

- **`create()`**（[L45-89](agent/digital_smart_doctor_agent.py#L45-L89)）：异步工厂 —— 建 MySQL 连接 → `AIOMySQLSaver` 作 checkpointer（多轮记忆存进 MySQL）→ 初始化 LLM → `_build_graph()`。
- **`_build_graph()`**（[L120-147](agent/digital_smart_doctor_agent.py#L120-L147)）：**用 `UnifiedSkillDispatcher` 直接替换旧 `SkillQueryNode`**（L130），构造 6 个节点。
- **`aprocess()`**（[L149-212](agent/digital_smart_doctor_agent.py#L149-L212)）：先看 checkpoint 是否有未完成状态 —— 没有则 `astream(init_state)`；有则 `aupdate_state` 继续跑（支持新一轮续跑与图片注入）。`restart=True` 会先走 `handle_restart` 恢复中断会话。
- **`_init_state()`**（[L214-251](agent/digital_smart_doctor_agent.py#L214-L251)）：初始 22+ 字段，含图片处理的状态机字段。

图结构见 [graph_builder.py](agent/core/graph_builder.py#L57-L113)：

```text
START → pre_process
          ├─ 有 image_path → image_process_node
          │          └─ 状态机：
          │             skill_executed → node_query_skills
          │             waiting_for_*  → node_empty（中断，等用户）
          │             idle → node_query_skills
          └─ 无图片 → node_query_skills（UnifiedSkillDispatcher.dispatch）
                        → node_chat（LLM 流式回答）
                        → node_suf_process（保存历史）
                        → node_empty（interrupt_after 中断点）
                              └─ chat_continue ? 回 pre_process : END
```

状态定义 [state.py](agent/core/state.py#L7-L33)：`image_processing_status` 四态（`idle / waiting_for_user_intent / waiting_for_skill_confirmation / skill_executed`）、`user_id`（租户标识）、患者信息、`sub_agent_input`（技能结果通道）等字段。

### 5.2 技能调度 —— 3-tier 匹配 + 统一执行（新架构核心）

入口 [UnifiedSkillDispatcher.dispatch()](skills/skills_optimize_srh/skill_dispatcher.py#L541-L618)：

**Phase 1 · 技能选择（3-tier）**
1. **Tier 1 关键词**（0ms）：[dynamic_registry.match()](skills/skills_optimize_srh/dynamic_registry.py#L243-L288) 遍历 `_BUILTIN_KEYWORD_MAP`（4 个内置技能的中文/英文关键词，如 `mysql_query` ← "就诊记录/病历/检查结果"）与用户自定义关键词 `_USER_KEYWORD_MAP`；
2. **Tier 2 FTS5**✅：[dynamic_registry._fts_search()](skills/skills_optimize_srh/dynamic_registry.py#L380) 内存 SQLite FTS5，为每个技能建"可检索文档"（name + description + keywords + triggers + SKILL.md 正文），中文 2-gram 预处理 + unicode61 索引，按命中比例排序召回 top-3；索引由 `_build_fts_index()`（[L331](skills/skills_optimize_srh/dynamic_registry.py#L331)）惰性重建；
3. **Tier 3 LLM 降级**：`select_skills()` 用 `with_structured_output(SkillSelectionResult)` 让 LLM 决定是否调技能、调哪些。选择前先生成"可用技能清单" —— 优先从 MySQL 查该医生启用的技能（[skills_prompt.py](prompt/skills_prompt.py#L14-L61)），失败则降级到注册表。

**Phase 2 · 并行执行**（[L591-598](skills/skills_optimize_srh/skill_dispatcher.py#L591-L598)）：`asyncio.gather` 并行执行，每个技能带超时（默认 300s）。

**执行路由**（`_execute_skill_core`，[L471-511](skills/skills_optimize_srh/skill_dispatcher.py#L471-L511)）：

| 技能类型 | 判定 | 执行方式 |
|---------|------|---------|
| 内置技能 | 在 `SKILL_REGISTRY` | `registry._execute_handler()`：准备数据 → LLM 生成结构化参数 → 调 Python handler → 失败自动重试 3 次 |
| 自定义（script） | `runner=subprocess_script`，有 execution.yaml/可自动发现入口 | `registry._execute_script()`：**直接 subprocess 执行**脚本，`.sh` 走 Git Bash、`.py` 走 python，`cwd` 限定技能目录，带超时 |
| 自定义（复杂） | `runner=llm_tool_loop` 或无法发现入口 | dispatcher `_execute_external_skill()`：经典 LLM 工具循环（最多 10 轮），加载 `make_skill_tools`，逐轮执行工具 |

> 💡 **为什么新架构快**：自定义技能从"LLM 工具循环（2–11 次 LLM 调用，10–50s）"改成"按 manifest 直接 `subprocess` 执行脚本（0.5–2s）"，见 [skill_dispatcher.py:278-284](skills/skills_optimize_srh/skill_dispatcher.py#L278-L284) 注释。

**Manifest 加载顺序**（[manifest.py](skills/skills_optimize_srh/manifest.py)）：`execution.yaml`（优先，声明 runner/entrypoint/keywords/timeout）→ `SKILL.md` frontmatter 推断 → 自动发现 `scripts/` 下 `.py/.sh` → 最终降级 LLM 工具循环。

### 5.3 动态注册与租户隔离

- `DynamicSkillRegistry` 用 **`"tenant_id:skill_name"`** 作 key 存 manifest（[dynamic_registry.py:148-183](skills/skills_optimize_srh/dynamic_registry.py#L148-L183)），支持运行时 `register_custom / unregister_custom / unregister_all_user`（热加载/注销）。
- **按需加载**：`dispatch()` 前调用 `_ensure_user_skills_loaded(user_id)`（[skill_dispatcher.py:620-671](skills/skills_optimize_srh/skill_dispatcher.py#L620-L671)），扫描 `user_skills/{user_id}/` 下的技能目录。
- **隔离**：`user_id` 由 `pre_process` 从 `chat_name`（如 `"姓名 1827196"`）用正则提取病历号获得；脚本执行 `cwd` 锁定在技能目录；其他用户的技能在关键词匹配时直接跳过（[dynamic_registry.py:271-274](skills/skills_optimize_srh/dynamic_registry.py#L271-L274)）。

### 5.4 一次对话的完整数据流

```text
用户输入（文本 / 图片）
   │
   ▼
[入口]  main.py / cli.py  /  chat_server.py POST /api/chat|stream
   │
   ▼
DigitalSmartDoctorAgent.aprocess(...)
   │  restart=True 时先 handle_restart；再检查 checkpoint 续跑 or 新开
   ▼
LangGraph 图
   ① pre_process        → 提取 user_id/病历号；解析 "!image" 上传命令
   ② image_process_node → 有图：Vision 描述 → 推荐 derma_image 等技能 → 状态机
   ③ node_query_skills  → UnifiedSkillDispatcher.dispatch
                          ├─ 技能选择（关键词匹配，未命中 → LLM 结构化输出）
                          └─ 并行执行技能（内置 handler / 脚本 / 工具循环）
   ④ node_chat          → 皮肤科系统提示词(qwen-plus) 流式生成回答
   ⑤ node_suf_process   → 本轮 human_input + final_answer 追加进 messages
   ⑥ node_empty         → 中断点；chat_continue 决定 回 ① / 结束
   │
   ▼
chunk 内容 → SSE data: {content} → 前端逐字渲染
```

## 6. 运行方式（速查）

详见 [`运行指南.md`](运行指南.md)。要点：

```bash
# 0) 安装依赖
uv sync

# 1) 后端双服务（两个终端）
uvicorn backend.main:app --port 8000          # 技能/医生管理
uvicorn backend.chat_server:app --port 8001   # 对话服务

# 2) 前端（第三个终端）
cd frontend && npm run dev                     # Vite，/api 代理到 8001

# 3) 或命令行直连对话（无需前端）
uv run python main.py                          # 朴素对话
uv run python cli.py                           # 带历史/彩色/命令的 Shell
```

> ⚠️ `application.yaml` 含**真实密钥**（LLM/MySQL/Milvus/Tavily），仓库不开源；开源前必须屏蔽（`.gitignore` 已有相关提示，[.gitignore:132-138](.gitignore#L132-L138)）。
> ⚠️ `vector/init/medicine_vector.py` 向量化药品库约 **0.3 亿 token / 单次约 15 元**，勿重复嵌入。
