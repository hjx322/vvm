# VVM Digital Smart Doctor Agent - 完整项目文档

## 📌 项目简介

**VVM Digital Smart Doctor Agent** 是一个 AI 驱动的医疗咨询系统，特别针对皮肤科诊断。它整合了大语言模型（LLM）与医学知识库、患者数据库，提供智能医疗咨询和皮肤病诊断辅助。

### 核心功能
- 💬 多轮医疗对话咨询
- 🏥 患者信息查询与管理
- 📚 医学知识库检索（药品、疾病、诊疗方案）
- 🖼️ 皮肤病智能识别（YOLO深度学习模型）
- 🌐 实时网络搜索最新医疗信息
- 🌤️ 中国天气查询
- 👤 多用户/多医生自定义技能管理

**项目类型**：生产级医疗 AI 系统
**开发语言**：Python 3.12
**状态**：活跃开发（最后更新：2026-03-26）

## 🧠 核心组件详解

### 1. Agent 层 (`agent/digital_smart_doctor_agent.py`)

**职责**：整体协调、状态管理、连接维护

```python
class DigitalSmartDoctorAgent:
  __init__()          # 初始化配置、数据库、LLM客户端
  create_workflow()   # 创建LangGraph状态机
  invoke()            # 执行单次推理
  stream()            # 流式处理
  close()             # 清理资源

  # 内部方法
  _create_connection()      # 带重试的MySQL连接
  _start_ping_task()        # 启动心跳检测
  _ping_loop()              # 定期健康检查
  _ensure_connection_alive()# 连接失败自动恢复
```

**关键特性**：
- ✅ 自动重连：失败重试3次（指数退避：2s→4s→8s）
- ✅ 心跳检测：每60秒执行SELECT 1
- ✅ 异常恢复：自动重新建立连接
- ✅ 线程安全：asyncio.Lock保护并发

### 2. 图处理流（LangGraph Nodes）

#### a. PreProcessNode（预处理节点）
```
功能：检测用户输入中是否有图片上传
输出：
  ├─ image_path != None  → 有图片，走ImageProcessNode
  └─ image_path == None  → 无图片，走SkillQueryNode
```

**检测逻辑**：
- 扫描文件系统（`./upload/`、`./images/`）
- 识别常见图片格式（.jpg, .png, .gif）
- 更新 `state.image_path`

#### b. ImageProcessNode（图片处理节点）
```
职责：处理已上传的图片
流程：
  1. 调用Vision API(千问视觉模型)获取图片描述
  2. 基于用户输入和图片内容检测意图
  3. 推荐相关技能或等待用户指令
  4. 执行技能或返回描述
```

**状态转移**：
```
idle → waiting_for_user_intent
  ├─ [用户明确指令] → waiting_for_skill_confirmation
  │                    ├─ 用户确认 → 执行技能 → skill_executed
  │                    └─ 用户拒绝 → idle
  └─ [无明确指令] → 等待用户输入
```

**技能关键词**：
- "皮肤病" → derma_image
- "检测" / "分析" → derma_image
- "天气" → clawhub_weather-cn
- 其他 → web_search

#### c. RoutingNode（路由节点）
```
决策逻辑：
┌─ image_processing_status == "skill_executed"
│  └─ 路由到 ChatNode（LLM总结）
│
├─ 存在待执行技能指令
│  └─ 路由到 SkillQueryNode
│
└─ 普通文本查询
   └─ 路由到 ChatNode 或 SkillQueryNode
```

#### d. SkillQueryNode（技能执行节点）
```
职责：调用注册的技能处理用户需求
流程：
  1. 解析用户输入
  2. 选择合适技能（可多个）
  3. 并行执行技能
  4. 格式化结果返回
  5. 处理错误和重试
```

**支持技能**：
```python
{
  "mysql_query": 患者信息查询,
  "milvus_query": 医学知识检索,
  "web_search": 网络搜索,
  "derma_image": 皮肤病检测,
  "clawhub_weather-cn": 天气查询
}
```

#### e. ChatNode（对话节点）
```
职责：调用LLM生成最终回答
输入：
  - 用户查询
  - 对话历史
  - 技能查询结果（如有）
  - 患者信息（如有）

输出：
  - final_answer: LLM生成的医疗咨询建议
```

**LLM配置**：
```yaml
model: qwen-plus
temperature: 0.2  # 低温度=确定性回答，适合医疗场景
api_base: https://dashscope.aliyuncs.com/compatible-mode/v1
```

#### f. PostProcessNode（后处理节点）
```
职责：格式化输出、清理状态、准备返回结果
操作：
  1. 提取关键信息
  2. 格式化为可读文本
  3. 清除中间状态
  4. 返回用户界面
```

### 2️⃣ milvus_query - 医学知识检索

**文件位置**：`.claude/skills/milvus_query/`

**职责**：向量化搜索医学知识库（两阶段检索）

**执行流程**：
```
用户查询词 (如: "脂溢性皮炎治疗")
  ↓
  ┌─────────────────────────────────────┐
  │      第一阶段：向量检索(Recall)      │
  └─────────────────────────────────────┘
  ├─ 将查询转化为向量
  ├─ 在Milvus向量库中搜索
  ├─ 返回Top-20相似文档
  ├─ 集合列表:
  │   ├─ drug_vector      (药品库)
  │   ├─ disease_vector   (疾病库)
  │   └─ gastroenterology_vector (消化科库)
  │
  ┌─────────────────────────────────────┐
  │     第二阶段：LLM重排(Rerank)       │
  └─────────────────────────────────────┘
  ├─ 将Top-20结果发送给LLM
  ├─ LLM进行语义相关性评分
  ├─ 返回Top-3最相关结果
  ├─ 优点：高相关性，过滤噪音
  └─ 启用开关: enable_reranking=True
  ↓
格式化输出给用户
```

**关键参数**：
| 参数 | 说明 | 默认值 |
|------|------|--------|
| operation | 操作类型 | "search" |
| enable_reranking | 启用LLM重排 | true |
| recall_k | 向量检索返回数 | 20 |
| rerank_top_k | LLM重排选取数 | 3 |

**使用示例**：
```python
{
  "operation": "search",
  "enable_reranking": True,
  "skill_list": [
    {
      "name": "drug_vector",
      "query": "阿司匹林用途",
      "recall_k": 20,
      "rerank_top_k": 3
    }
  ]
}
```

**何时触发**：
- ✅ 用户询问药品信息
- ✅ 用户询问疾病症状/治疗
- ✅ 用户寻求医学建议
- ❌ 非医学话题（天气、娱乐）

## 📊 LLM配置

### DashScope（阿里巴巴）

**API兼容**：OpenAI格式

**配置示例**：
```yaml
llm:
  default: qwen-plus
  dashscope:
    api_key: "${DASHSCOPE_API_KEY}"
    api_base: "https://dashscope.aliyuncs.com/compatible-mode/v1"
    model: "qwen-plus"
    temperature: 0.2
    timeout: 60
```

**为何选择QWEN Plus**：
- ✅ 医学知识库较好
- ✅ 多语言支持
- ✅ 成本相对低
- ✅ 延迟可接受

**Temperature = 0.2**：
- 低值 → 回答确定性高、重复性强
- **医疗场景**：需要准确、一致的建议
- **不适合**：创意、多样化回答

### 视觉模型（千问Vision API）

**用途**：分析用户上传的医学图片

**调用流程**：
```python
async def describe_image(image_path: str) -> str:
    """使用千问Vision API描述图片内容"""
    client = AsyncOpenAI(api_key=api_key, base_url=api_base)

    with open(image_path, "rb") as f:
        image_data = base64.b64encode(f.read()).decode()

    response = await client.chat.completions.create(
        model="qwen-vl-plus",
        messages=[{
            "role": "user",
            "content": [
                {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{image_data}"}},
                {"type": "text", "text": "描述这张医学图片的内容和特征"}
            ]
        }]
    )
    return response.choices[0].message.content
```

**连接管理**：
```python
# 多层级保活机制
1. Agent级别(aiomysql)
   └─ 自动重连：3次重试，指数退避
   └─ 心跳检测：每60秒SELECT 1

2. 连接池级别(SQLAlchemy)
   └─ 连接回收：1小时自动清理
   └─ 预检查：获取连接前ping验证

3. 查询级别
   └─ 重试机制：失败自动重试最多3次
```

### Milvus - 医学知识向量库

**集合结构**：
```
drug_vector
├─ id: 药品编号
├─ name: 药品名称
├─ embedding: 向量(1536维)
└─ metadata: 通用名、规格、价格等

disease_vector
├─ id: 疾病编号
├─ name: 疾病名称
├─ embedding: 向量
└─ metadata: 症状、治疗、ICD编码

gastroenterology_vector
├─ 消化科相关知识
├─ embedding: 向量
└─ metadata: 内容来源、更新时间
```

**两阶段检索**：
```
向量搜索(Recall阶段)
  └─ Milvus返回Top-20相似文档
    ├─ 计算速度快
    ├─ 包含边界案例
    └─ 可能相关度不完全一致

LLM重排(Rerank阶段)
  └─ 将Top-20发送给LLM
    ├─ LLM评估语义相关性
    ├─ 返回Top-3最相关结果
    ├─ 过滤噪音和不相关结果
    └─ 提升最终答案质量
```

**优势**：
- ✅ 提高相关性准确度
- ✅ 减少假正例
- ✅ LLM理解上下文
- ⚠️ 增加延迟(LLM调用)

```python
# skills/my_skill_handler.py
from skills.base import SkillHandler
from pydantic import BaseModel

class MySkillSchema(BaseModel):
    param1: str
    param2: int = 10

class MySkillHandler(SkillHandler):
    def __init__(self):
        super().__init__("my_skill")

    async def execute_with_llm_async(self, state, llm_client):
        """执行技能"""
        # 1. LLM生成参数
        params = await self.generate_params_with_llm(
            state, llm_client, MySkillSchema
        )

        # 2. 执行逻辑
        result = await self.execute_logic(params)

        # 3. 格式化结果
        return self.format_result(result)
```

## 📊 性能优化建议

| 瓶颈 | 当前方案 | 优化方向 |
|------|---------|--------|
| **LLM延迟** | 平均1-2s | 缓存提示词、batch处理 |
| **MySQL查询** | 直连 | 添加查询结果缓存 |
| **Milvus检索** | 单集合搜索 | 并行多集合搜索 |
| **图片处理** | 同步YOLO推理 | GPU加速、模型量化 |
| **Vision API** | 每次调用 | 缓存描述结果 |

**推荐优先级**：
1. 🔴 高：LLM响应缓存(减少API调用)
2. 🟡 中：异步并行执行(减少顺序等待)
3. 🟢 低：数据库查询优化(已有重连机制)
